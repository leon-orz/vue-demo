# Toogl 开发状态与方向

> 本文记录实现进度、待人工验收清单、已知缺口和开发方向；能力边界见 [产品说明](01-产品说明.md)，架构事实见 [架构与数据流](02-架构与数据流.md)。文档只记录当前代码事实，不把目标方案写成已完成。

## 当前进度（2026-10）

### 已实现

- **应用壳**：模块编译时登记（`app/modules.ts`）、hash 路由、看板布局与卡片级错误边界、主题偏好（亮/暗/跟随系统）。
- **规划中占位入口（2026-10 UI 设计）**：五个未实现模块已登记导航（`/feed`、`/ai-gateway`、`/system-tuning`、`/network-tuning`、`/dev-environment`），统一渲染 `PlannedPlaceholder.vue` 占位页；侧栏"规划中"分组带虚线徽标，看板有规划中功能摘要卡。占位页不发起业务 IPC。
- **魔法工具**：mihomo sidecar 生命周期、代理组/节点查看与切换、规则模式、系统代理备份与恢复、订阅 + 手动导入、批量测速、异常残留恢复、24 小时后台订阅更新。

### 已清理（2026-10 大更新）

旧版「网络诊断」「系统状态」「空间维护」三模块已整体移除（前端模块目录、`system_tools` 相关 commands/models/core 实现、`CleanupScan`/`NetworkDiagnostic`/`NetworkRepairResult`/`SystemInformation` 类型与 bindings、孤儿工具函数 `formatBytes`），由规划中的「系统优化」「网络优化」接替。旧实现的待验收项随之作废。

## 待人工验收清单

以下行为依赖真实桌面环境（sidecar、注册表、系统代理），无法用单测覆盖，需在运行中的应用里验证：

- [ ] 魔法工具：启动 → 开系统代理 → 退出后系统代理恢复为原值。
- [ ] 魔法工具：异常结束进程后再次启动，出现残留提示并可一键恢复。
- [ ] 魔法工具：订阅更新失败时保留旧节点，界面提示错误明细。
- [ ] 看板：魔法工具卡 IPC 失败只降级该卡，规划中占位卡照常渲染。
- [ ] 主题切换在重启应用后保持。

## 已知缺口

- 看板实现卡目前只有魔法工具一张，其余模块实现后补充。
- 五个规划中模块仅占位：信息订阅、AI 网关、系统优化、网络优化、开发环境。信息订阅需求细节、AI 网关平台 API 仍未确定；占位页文案不构成能力承诺。
- 无覆盖率门槛与 e2e 套件；质量依赖 CI 静态检查 + 单测 + 人工验收。

## 开发方向

1. **信息订阅模块**：确定 RSS/GitHub 源的展示结构与刷新策略后设计 IPC 与模型。
2. **AI 网关模块**：等待平台 API；届时先定凭据存储方案（`toogl.db`，展示脱敏），再定用量/状态模型。
3. **系统优化 / 网络优化 / 开发环境**：按"只读检查自动、修改动作逐项确认"的边界逐个设计，先出交互稿再写代码。
4. 每接入一个新模块：登记 `modules.ts` → 补看板卡 → 更新四份文档与验收清单。
