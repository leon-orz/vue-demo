# Toogl 模块开发指南

> 本文规定新增模块的接入步骤、代码组织与完成标准；产品边界见 [产品说明](01-产品说明.md)，架构事实见 [架构与数据流](02-架构与数据流.md)。

## 新增模块步骤

1. **登记**：在 `apps/desktop/src/app/modules.ts` 追加 `ToolModule`（`id`、`title`、`icon`、`route`，可选 `dashboard` 卡）。模块从此出现在导航与看板。若该模块此前已按"规划中"占位登记，则替换 `route.component` 为正式页面、删除 `planned` 字段、补看板卡，并在 `docs/03` 更新进度。
2. **目录**：新建 `apps/desktop/src/modules/<id>/`，按下方组织方式落文件，README 简述逻辑链路。
3. **IPC**：Rust 侧在 `crates/core/src/` 实现业务，`apps/desktop/src-tauri/src/commands/` 加薄壳命令并在 `lib.rs` 登记；前端 `api.ts` 与命令一一对应。
4. **类型**：新 DTO 定义在 `crates/core/src/models/`，跑 `cargo test -p toogl-core export_bindings` 生成 TS 类型；前端用 `import type` 引用 `@toogl/core-types`。
5. **持久化**（如需）：偏好走 `PreferenceStore` 类型化 namespace；新表走 `crates/core/migrations/NNNN_description.sql` 并追加 `db.rs::MIGRATIONS`。
6. **文档**：更新 [产品说明](01-产品说明.md)（能力与边界）、[架构与数据流](02-架构与数据流.md)（IPC 清单、数据流）、[开发状态与方向](03-开发状态与方向.md)（进度、验收项）。

## 代码组织

```text
modules/<id>/
  <Id>.vue                 # 页面装配
  api.ts                   # invoke 薄映射，一一对应
  store.ts / use*.ts       # 状态（Pinia 或组合式），错误经 toCommandError 规整
  components/              # 展示组件
    OverviewCard.vue       # 可选：看板摘要卡
  README.md                # 逻辑链路简述
  *.spec.ts                # 邻近源码的测试
```

- `components/ui/` 仅基础 UI；跨模块交互放 `shared/`；纯函数放 `lib/`。不复制实现、不加空服务层。
- 看板卡只做摘要与入口，不复制模块业务公式；单卡加载失败由 `ModuleCardBoundary` 降级。

## API 与状态规则

- 顶层 invoke 参数 camelCase；DTO 字段遵循生成类型的 serde 命名；类型用 `import type`。
- commands 返回 `Result<T, CommandError>`；Rust 内部错误用 thiserror，`CommandErrorKind` 用生成枚举。
- 异步约定：初始化请求复用；后台刷新保留可用缓存；旧响应不覆盖新状态；轮询成对启停、跳过隐藏窗口、跳过在途请求；乐观更新失败回滚。
- 依赖注入沿用显式 trait 接缝（参考 `sysproxy.rs` 的 `RegistryIo` / `ProxyStateStore`），测试注入内存实现。

## 安全边界（所有模块通用）

- 不接受前端传入任意命令、路径、脚本或配置键；系统能力使用固定可执行文件、固定参数或白名单。
- 破坏性动作（改系统设置、结束进程、删除文件）必须先展示受影响对象并逐次确认。
- 凭据只存本机数据库，不进日志，前端展示脱敏。
- 网络访问目标固定或来自用户显式配置；不执行外部内容中的脚本。

## 测试要求

- 前端 Vitest + jsdom，`*.spec.ts` 邻近源码；重点覆盖状态转换、轮询/失败回滚、错误处理与 IPC 契约。组件测试从简，不写脆弱快照。
- Rust `#[cfg(test)]` 单测；HTTP 用 wiremock，数据库用隔离 SQLite，注册表等系统能力用内存 mock。
- 纯展示、纯转发、mock 回声不写测试；用一次性脚本冒烟。
