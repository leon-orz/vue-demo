# Toogl 模块开发指南

> 本指南适用于首页看板、魔法工具、网络诊断、系统状态、空间维护和软件设置。
> 新模块先明确用户任务、数据来源、生命周期和失败语义，再进行编译时接入；不创建空接口或尚无调用方的通用抽象。

## 1. 模块分类

### 1.1 首页看板

看板是固定入口，不是业务模块。它负责：

- 加载已登记的摘要卡；
- 按统一布局展示各模块状态；
- 隔离单个卡片的加载和错误；
- 提供进入模块的入口。

看板不得：

- 直接调用 mihomo、Windows API 或文件扫描能力；
- 导入模块 Store 后重新计算状态；
- 复制模块的业务公式、错误判断和数据转换；
- 在卡片之外维护业务配置。

### 1.2 核心模块：魔法工具

魔法工具负责 mihomo 生命周期、节点和代理组、规则模式、系统代理、订阅、手动导入、测速和异常恢复。

它是当前投入优先级最高的模块，但不因此删除或隐藏其他模块。

### 1.3 基础工具模块

- `network-diagnostics`：固定 DNS/TCP 检查和 DNS 缓存刷新。
- `system-status`：Windows 与设备只读信息。
- `storage`：当前用户 Temp 目录安全扫描，不自动删除。
- `settings`：Toogl 主题和版本信息。

基础工具模块保持单一任务，不把多个不相关动作继续堆进名为“系统工具”的大页面。

## 2. 新增或拆分模块的最小步骤

1. 在 `docs/01-需求文档.md` 写清用户任务、范围、数据来源、配置、生命周期、失败和安全边界。
2. 确认功能不属于已有模块，且有实际调用方；不要为了未来扩展预建目录或接口。
3. 在 `apps/desktop/src/modules/<id>/` 创建页面；按复杂度增加 `api.ts`、`store.ts`、`components/` 和测试。
4. 在 `apps/desktop/src/app/modules.ts` 登记稳定 ID、标题、图标、路由和可选 `OverviewCard.vue`。
5. 模块摘要卡只读取本模块状态，并提供进入本模块的路径或处理入口。
6. 需要本地业务时在 `crates/core/src/<module>/` 实现；Tauri commands 只负责 State、调用和错误映射。
7. 在 Rust `models/` 定义跨语言类型，运行导出测试生成 `packages/core-types/bindings/`。
8. 更新需求、开发计划和人工验收说明；运行与改动直接相关的检查。

不需要为每个模块在软件设置页增加配置表单，也不需要把模块注册到远程服务或运行时插件系统。

## 3. 推荐目录

复杂模块：

```text
modules/<id>/
  <Name>.vue               主页面
  api.ts                   与 Tauri commands 一一对应
  store.ts                 模块状态、刷新和动作
  store.spec.ts            关键状态转换和错误回滚
  components/
    OverviewCard.vue       可选：看板摘要卡
    <Panel>.vue            模块内部面板
```

小模块可以只有：

```text
modules/<id>/
  <Name>.vue
  api.ts
```

不要为了统一结构创建空的 Store、空的 Configuration 或空的服务层。

当前基础模块使用 `useNetworkDiagnostics.ts`、`useSystemInformation.ts`、`useStorageScan.ts` 管理页面局部状态，不为单页面状态强制引入 Pinia。
系统盘信息由系统状态模块公开的 composable 提供给空间维护；不能通过复制查询实现消除合理依赖。
应用壳专用组件放在 `app/components/`，不放进通用 `components/ui/`；字节格式化等纯函数放在 `lib/`。

## 4. 模块登记规则

`apps/desktop/src/app/modules.ts` 是唯一登记点：

- 模块数组顺序就是导航顺序。
- 路由页面使用动态 import。
- 摘要卡使用 `defineAsyncComponent` 按需加载。
- ID 稳定后不得因显示名称变化而修改。
- 业务模块需要有明确路由；纯首页布局不重复登记。
- 摘要卡可选；只有有稳定、可复用状态时才提供。
- 看板不通过复制数组或单独配置表登记卡片。

建议当前登记顺序：

```text
看板 → 魔法工具 → 网络诊断 → 系统状态 → 空间维护 → 设置
```

## 5. API、Store 和状态规则

### 5.1 API

- `api.ts` 的每个函数与一个 Tauri command 对应。
- 参数顶层使用 camelCase；DTO 字段使用生成 bindings 的 serde 命名。
- 返回类型来自 `@toogl/core-types`，不在前端重复声明 Rust 模型。
- 无参数命令不要人为传空对象，按 Tauri 契约保持一致。
- API 不做业务合并、解析和系统副作用。

### 5.2 Store

Store 负责：

- 模块状态；
- 加载状态和错误；
- 页面可见期间的轮询；
- 防止重复请求；
- 动作锁；
- 乐观更新和失败回滚；
- 将模块状态提供给详情页和摘要卡。

Store 不负责：

- 其他模块页面状态；
- 全局事件总线；
- 未有调用方的缓存抽象；
- 代替 Rust 保存业务事实。

刷新规则：

- 首次进入立即请求；
- 在途请求不叠加；
- 页面卸载必须停止轮询；
- 窗口隐藏时跳过非必要刷新；
- 后台刷新失败不清空仍可用的缓存；
- 旧响应不能覆盖更新后的状态。

### 5.3 摘要卡

摘要卡应：

- 复用所属模块 Store/API；
- 展示少量高价值状态；
- 明确未配置、未检查和错误状态；
- 提供进入模块或重试的入口；
- 不因为详情页未打开而启动不必要的长期轮询。

## 6. 各模块特殊边界

### 6.1 魔法工具

- mihomo `/version` 是存活事实源。
- mihomo `/proxies` 是代理组和当前节点事实源。
- mihomo `/configs` 是规则模式事实源。
- 系统代理实际状态来自 Windows registry。
- 开启前备份，关闭/退出恢复；异常退出后提供恢复路径。
- controller 默认只监听回环并使用随机 secret。
- 订阅和手动导入共享更新互斥。
- 热重载失败回滚节点文件；更新失败保留旧节点。
- 用户手写非模板配置不得静默改写。
- 当前只支持系统代理，不实现 TUN、PAC、虚拟网卡和进程代理。

### 6.2 网络诊断

- 目标固定，不接受前端传入任意 URL、命令、路径或脚本。
- DNS 最长 5 秒，TCP 最长 3 秒。
- DNS 失败或超时不执行 TCP。
- `ipconfig.exe` 必须使用系统目录中的固定可执行文件和固定 `/flushdns` 参数。
- 结果只描述测试目标，不能推断整网状态。
- 不自动重置网卡、代理或网络配置，不自动提权。

### 6.3 系统状态

- 通过 Windows 只读系统 API 获取事实。
- 展示 Windows 版本、设备名、处理器、物理内存和系统盘空间。
- 不以环境变量替代系统版本。
- 不加入注册表优化、内存清理或系统修改动作。

### 6.4 空间维护

- 只扫描 `%LOCALAPPDATA%\\Temp`。
- 根目录是重解析点时拒绝扫描。
- 子项符号链接和其他重解析点跳过。
- 限制扫描量、文件数量和执行时间。
- 第一阶段不删除文件，不接受任意路径。
- 未来删除能力必须逐项确认并返回逐项结果，不能做静默一键清理。

### 6.5 软件设置

- 只管理 Toogl 自身偏好。
- 当前为主题和版本信息。
- 不把代理、订阅、诊断和扫描配置放入软件设置。
- 未实现的开机自启、窗口行为、置顶和 TUN 不得显示为开关。

## 7. Rust 核心和持久化

- 业务解析、文件 IO、Windows 系统调用、订阅合并和错误编排放入 `crates/core`。
- commands 统一返回 `Result<T, CommandError>`，不在命令层复制业务逻辑。
- Rust 内部错误使用 thiserror；`CommandErrorKind` 使用生成枚举，不另写字符串集合。
- SQLite 迁移只追加，版本登记和迁移在同一事务中完成。
- 读取失败不能被当作首次使用并写回默认值。
- 只有确有敏感数据需求时才设计安全存储；不预设凭据接口。
- Rust models 是跨语言契约唯一来源；bindings 禁止手改。

## 8. 测试要求

前端：

- Store 测试覆盖状态转换、轮询启动/停止、防重复请求、失败回滚和缓存保留。
- IPC 契约测试覆盖命令名称、参数键和关键返回类型。
- 看板测试重点验证卡片加载隔离和模块入口，不测试复制出来的业务公式。
- 组件测试从简，避免脆弱快照。

Rust：

- 订阅解析覆盖合法格式、坏行、无有效节点和同名合并。
- 更新覆盖热重载成功、失败回滚、旧节点保留和并发拒绝。
- 系统代理使用注册表 mock，不修改真实系统现场。
- 网络诊断覆盖 DNS 失败不继续 TCP、超时和固定命令。
- Temp 扫描覆盖根目录重解析点、子项链接跳过和扫描上限。
- 数据库测试使用隔离 SQLite。

真实桌面验收：涉及 sidecar、系统代理、订阅、CSP、WebView2 和 NSIS 的改动必须在 Windows 真实环境验证，单元测试不能替代。

## 9. 完成标准

- 导航、看板和模块页面可进入；入口与路由一致。
- 首页看板显示所有已登记模块，魔法工具突出但不隐藏其他模块。
- 摘要卡和详情页使用相同数据口径。
- 空数据、未检查和失败状态可解释。
- 配置持久化和旧值兼容符合模块边界。
- 无未清理轮询、重复初始化、过期响应覆盖或退出残留。
- 核心业务和系统能力下沉 Rust，bindings 与模型一致。
- 文档只描述已实现事实或明确标注计划，不把计划功能写成完成。
