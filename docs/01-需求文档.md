## 1. 项目背景与目标

### 1.1 背景

这是一个**个人自用**的 PC 桌面工具箱软件（正式名 **Toogl**，中文名"**图格**"），把作者日常散落在各处的工具集中到一个应用里。当前存在两大痛点：

1. **AI 用量看不清**：作者使用 Kimi Code 套餐（kimi-code CLI）做 AI 编程，用量散落在 CLI 的本地日志里（`wire.jsonl`），没有聚合视图，token 消耗、缓存命中率、配额余量都看不到；余额/配额要登录网页查询。
2. **代理管理分散**：有境外 VPS 自建代理（稳定 IP，专给 Codex/Claude 等编程工具使用），节点切换、系统代理开关、按域名分流都要手动操作 Clash 系客户端，不够顺手。

### 1.2 目标

| #   | 目标                                                                             | 衡量方式                                                                                       |
| --- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| G1  | Kimi Code 用量一目了然                                                           | 打开软件即可看到今日/本周/本月 token 消耗、缓存命中率、按 CLI/模型/项目分布，无需翻日志         |
| G2  | Kimi 配额/余额在软件内可查                                                       | Kimi 5 小时窗口与用量（best-effort）、开放平台余额在软件内可查，无需登录网页                   |
| G5  | 魔法工具核心三样（节点切换、系统代理开关、规则组切换）+ 延迟测试 + AI 域名分流在软件内完成 | 不再单独打开 Clash 客户端面板；api.openai.com / anthropic.com 等域名强制走稳定节点组           |

### 1.3 非目标

见第 7 章"范围边界"。

## 2. 名词解释

| 名词              | 通俗解释                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| wire.jsonl        | Kimi Code 在本机写的会话日志文件（位于 `~/.kimi-code/sessions/**/`），每行一条 JSON 记录，每次 API 请求的记录里带 usage 字段。是本软件 Kimi 用量统计的数据源。 |
| usage 字段        | wire.jsonl 中每次请求的用量记录：`inputOther`（普通输入 token）、`output`（输出 token）、`inputCacheRead`（缓存命中 token）、`inputCacheCreation`（缓存写入 token）。 |
| 缓存命中 / 缓存写入 | Kimi 的上下文缓存机制：命中缓存的输入 token（inputCacheRead）单价更低；首次写入缓存的 token（inputCacheCreation）单独计价。缓存命中率是衡量用量成本效率的关键指标。 |
| 5 小时滚动窗口    | Kimi Code 包月的限流窗口：官方按最近 5 小时内的用量限制速率。软件用本地日志聚合出"最近 5 小时用量"作为近似值。                                                  |
| Kimi Code 套餐    | Kimi 官方编程订阅套餐（kimi-code CLI 使用）：5 小时滚动窗口限流 + 月度池。用量接口为非官方 `GET /coding/v1/usages`，best-effort 查询。                          |
| mihomo            | Clash 系代理内核（原 Clash.Meta），提供 RESTful API（默认 9090 端口）。软件把它作为 sidecar 内置，实现节点切换、延迟测试、系统代理开关、按域名分流。            |
| 系统代理          | 操作系统级的代理开关，打开后大部分应用的流量自动走代理。                                                                                                       |
| 规则组 / 分流     | 按域名等规则决定流量走哪个节点或直连。本项目要求 api.openai.com、anthropic.com 等域名强制走"稳定节点组"。                                                       |
| Tailscale         | 组网工具，把多台设备组成一个私有网络。设备与 VPS 用它互联，服务不开公网端口。                                                                                 |
| Tauri 2           | 用 Web 前端 + Rust 后端构建轻量桌面应用的框架。                                                                                                               |
| 钥匙串            | 操作系统自带的凭据安全存储（Windows 凭据管理器等），用于加密保存敏感 key。                                                                                    |

## 3. 用户与设备角色

**用户**：单一用户（作者本人），个人自用，无多用户、无权限体系。

### 3.1 设备角色

| 设备     | 角色         | 运行内容                              |
| -------- | ------------ | ------------------------------------- |
| 笔记本   | 全功能客户端 | Toogl 桌面客户端（Tauri 2 + Vue 3）   |
| 台式机   | 全功能客户端 | Toogl 桌面客户端（同上）              |
| 境外 VPS | 代理出口     | 只跑代理服务端（mihomo/sing-box），Tailscale 组网 |

### 3.2 角色关系说明

- 客户端是功能入口，本地可独立完成 AI 用量统计（CLI 日志解析）、魔法工具等全部功能。
- VPS 不参与统计与控制链路，只作为魔法工具的代理节点来源。

## 4. 功能需求

优先级定义：

- **P0**：阶段内必须完成，缺了不算交付。
- **P1**：阶段内尽量完成，可以砍但要有记录。
- **P2**：增强项，有时间再做或排到后续阶段。

阶段标注与《02-开发计划》一致：阶段一（纯软件，不依赖新硬件）、阶段三（深度功能与增强）。

### M1 AI 用量统计

**目标**：Kimi Code 的用量与配额/余额一目了然。本模块为**只读聚合，不转发任何流量**。

数据源（指标策略为 best-effort：日志里有什么看什么）：

| 平台/套餐      | 计费                            | 主要 CLI  | 本地日志来源                              | 配额/余额来源                                            |
| -------------- | ------------------------------- | --------- | ----------------------------------------- | -------------------------------------------------------- |
| Kimi Code 套餐 | 订阅（5h 滚动窗口 + 月度池）    | kimi-code | `~/.kimi-code/sessions/**/wire.jsonl`     | 开放平台 `GET /v1/users/me/balance` 余额 + 非官方 `GET /coding/v1/usages`，best-effort |

排除项：Codex CLI 日志不支持（一年用一两次）；GLM 套餐不列入。

| 编号  | 功能点                                                                                 | 优先级             | 说明                                                                                                   |
| ----- | -------------------------------------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------ |
| M1-01 | kimi-code wire.jsonl 日志的增量解析                                                    | P0（阶段一，S1-4） | 统一事件模型：cli + platform + model + 四类 token（输入/输出/缓存命中/缓存写入）+ 项目；增量解析，不全量重扫 |
| M1-02 | token 消耗聚合统计                                                                     | P0（阶段一，S1-4） | 按四类 token 分别汇总                                                                                  |
| M1-03 | 缓存命中率统计                                                                         | P0（阶段一，S1-4） | 缓存命中占输入总量比例                                                                                 |
| M1-04 | 按天 / 周 / 月用量趋势视图                                                             | P0（阶段一，S1-4） |                                                                                                        |
| M1-05 | 按 CLI / 模型 / 项目分布统计                                                           | P0（阶段一，S1-4） | 项目名取自会话元数据（kimi-code 会话目录 state.json 的 cwd）                                            |
| M1-06 | Kimi 最近 5 小时用量 + 套餐用量接口（`GET /coding/v1/usages`）+ 开放平台余额           | P0（阶段一，S1-4） | 用量接口为非官方接口，best-effort：失败时降级为仅本地日志聚合的 5h 近似值，界面标注数据来源              |
| M1-09 | 用量估值（按单价表估算成本）                                                           | P1（阶段一）       | 单价表迁移为 M6 可配置项                                                                               |
| M1-10 | 统计数据本地缓存（SQLite），配额/余额支持手动/定时刷新                                 | P0（阶段一，S1-4） | 刷新间隔可配置，默认值待定                                                                             |
| M1-11 | 历史趋势图表增强                                                                       | P2（阶段三）       | 日志解析始终在客户端本地执行                                                                           |

说明：纯本地日志统计（wire.jsonl）不需要任何 key，仅配额/余额查询类接口需要 Kimi key。

### M5 魔法工具

**目标**：代理的常用操作在软件内完成，内置 mihomo 作为 sidecar。

实现方式：软件内置 mihomo 内核（Clash 系，提供 RESTful API，默认 9090 端口），通过其 API 实现控制。**一期只做核心三样**（节点切换 + 系统代理开关 + 规则组切换）+ 延迟测试 + AI 域名分流。

| 编号  | 功能点                                                                       | 优先级       | 说明                                                                                                                                           |
| ----- | ---------------------------------------------------------------------------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| M5-01 | mihomo sidecar 的启动/停止与生命周期管理                                     | P0（阶段一） | 随软件启动、退出时收尾                                                                                                                         |
| M5-02 | 节点切换                                                                     | P0（阶段一） | 核心三样之一                                                                                                                                   |
| M5-03 | 系统代理开关                                                                 | P0（阶段一） | 核心三样之一                                                                                                                                   |
| M5-04 | 规则组切换                                                                   | P0（阶段一） | 核心三样之一                                                                                                                                   |
| M5-05 | AI 域名分流：api.openai.com、anthropic.com 等强制走"稳定节点组"              | P0（阶段一） | 稳定 IP 专给 Codex/Claude 使用                                                                                                                 |
| M5-06 | 延迟测试                                                                     | P1（阶段一） |                                                                                                                                                |
| M5-07 | 节点/订阅配置导入与更新                                                      | P1（阶段一） | **导入方式：订阅链接 + 定时更新为主**（用户当前为商家包月订阅用户），手动粘贴分享链接（vless://、hysteria2:// 等）/yaml 片段为辅（后续自建 VPS 用）；订阅更新失败保留旧节点并告警 |
| M5-08 | 分流规则的软件内编辑界面                                                     | P2（阶段三） | 一期规则以配置文件方式维护                                                                                                                     |

> 已知限制（已确认）：阶段一仅做**系统代理**模式，不做 TUN——不读系统代理设置的终端 CLI（部分 AI 编程 CLI 属此类）流量不经过 mihomo，M5-05 的 AI 域名分流对它们不生效；TUN 需管理员提权，后续按需评估。**M5 目标场景为软件与网站，不考虑游戏**。

## 5. 非功能需求

### 5.1 安全

| 编号  | 需求                                                                                                       |
| ----- | ---------------------------------------------------------------------------------------------------------- |
| NF-01 | 所有敏感凭据（Kimi API key 等）加密存操作系统钥匙串，**不以明文写入配置文件或 SQLite**。                   |
| NF-02 | 设备与 VPS 之间通信走 Tailscale 私有网络，服务**不开公网端口**。                                           |
| NF-03 | AI 用量数据全部**本地采集**（CLI 日志）+ 平台官方/半官方 API **直连**，不经任何中转/网关转发。             |
| NF-04 | mihomo 的 RESTful API 只监听本机回环地址，不对外暴露。                                                     |

### 5.2 性能

| 编号  | 需求                                                                                                       |
| ----- | ---------------------------------------------------------------------------------------------------------- |
| NF-06 | 客户端常驻内存目标 **< 200MB**（不含 mihomo sidecar；sidecar 自身开销单独观察，暂不设硬指标）。            |
| NF-07 | Dashboard 与各模块页打开即读本地缓存，拉数/解析异步进行，不阻塞界面。                                       |
| NF-08 | CLI 日志解析必须增量进行（记录已解析位置/偏移），日志文件增大后每次刷新只读增量部分。                       |

### 5.3 可扩展性

| 编号  | 需求                                                                                                       |
| ----- | ---------------------------------------------------------------------------------------------------------- |
| NF-09 | 数据获取层做成可替换接口（DataSource），为后续接入新数据源预留。                                           |

### 5.4 可靠性

| 编号  | 需求                                                                                                       |
| ----- | ---------------------------------------------------------------------------------------------------------- |
| NF-12 | 单个数据源失败（如平台 API 超时、某次日志解析异常）不影响其他模块展示，失败状态在界面上可见。              |
| NF-13 | 解析外部 CLI 日志（wire.jsonl）必须**容错**：格式随 CLI 版本变化可能出现异常行/异常字段，跳过并计数，不中断整体解析。 |

### 5.5 平台支持

| 编号  | 需求                                                                                  |
| ----- | ------------------------------------------------------------------------------------- |
| NF-14 | 客户端目标平台：**仅 Windows**（已确认，作者设备均为 Windows；macOS/Linux 桌面端不做）。 |

## 7. 范围边界（明确不做）

| 不做项                             | 说明                                                                                                                                           |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **API 中转 / 网关**                | 软件对 AI 平台只读统计，不转发任何流量                                                                                                         |
| **Codex CLI 日志支持**             | 用户一年用一两次，明确不支持其日志解析；GLM 套餐不列入                                                                                         |
| **第三方中转平台的余额/用量统计**  | 用户明确不需要                                                                                                                                 |
| **Kimi Code 限额余量精确抓取**     | 官方无正式 API；M1-06 的非官方 `coding/v1/usages` 接口为 best-effort，失败时降级为本地日志聚合的"最近 5 小时用量"近似参考                      |
| 手机端                             | 远期方向，阶段三之后再说                                                                                                                       |
| 多用户 / 权限体系                  | 个人自用，无此需求                                                                                                                             |
| 消息推送（如余额告警推送）         | 远期方向                                                                                                                                       |
| 魔法工具的完整功能集               | 一期只做核心三样 + 延迟测试 + AI 域名分流；规则编辑界面排阶段三                                                                                |
