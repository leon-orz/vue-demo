# Toogl（图格）产品需求文档

> Toogl 是面向 Windows 10/11 的个人桌面实用工具箱。
> 首页看板统一展示各模块状态，魔法工具是核心模块；网络诊断、系统状态、空间维护和软件设置提供独立的基础能力。
> 本文定义产品范围与行为；工程实现和阶段安排见《02-开发计划》，模块接入规则见《03-模块开发指南》。

## 1. 产品定位与原则

Toogl 解决个人用户在 Windows 上的几个高频任务：使用 mihomo 代理、判断网络状态、查看系统概况、扫描临时空间，以及管理应用自身偏好。

产品原则：

- 魔法工具是最重要、最完整、验收优先级最高的模块。
- 首页看板必须保留，负责汇总各模块状态并提供入口。
- 其他模块不隐藏、不取消，但保持边界小、行为可解释。
- 看板不复制模块业务逻辑；摘要卡由所属模块提供状态和展示。
- Windows 10/11 是唯一桌面平台；不扩展 macOS/Linux。
- 先完成基础可用闭环，再评估高级能力。
- 不以“优化”为名静默修改系统设置或删除用户文件。

当前不承诺：TUN、远程 Hub、远程数据源、手机端、多用户、AI API 网关、游戏加速、代理流量计费或统计平台。

## 2. 信息架构

一级入口固定为：

| 入口 | 作用 | 是否提供看板摘要 |
| --- | --- | --- |
| 首页看板 | 汇总模块状态，提供处理入口 | 否 |
| 魔法工具 | 管理 mihomo、节点、模式、系统代理和节点来源 | 是，最高优先级 |
| 网络诊断 | 执行固定 DNS/TCP 检查和 DNS 缓存刷新 | 是 |
| 系统状态 | 只读查看 Windows 与设备基础信息 | 是 |
| 空间维护 | 扫描当前用户临时目录，展示空间概况 | 是 |
| 软件设置 | 管理 Toogl 自身主题和版本信息 | 可选 |

看板是固定入口；业务模块通过编译时登记接入导航和摘要卡。模块顺序由登记表决定，不另设运行时插件或远程模块发现机制。

## 3. 首页看板

### 3.1 目标

用户打开 Toogl 后，先知道代理、网络和系统状态，再进入具体模块处理问题。看板不取代模块页面，也不承担复杂操作。

### 3.2 内容

- 魔法工具卡：内核是否运行、系统代理状态、当前模式、当前节点、订阅状态和异常恢复入口。
- 网络诊断卡：最近一次诊断结果、DNS/TCP 状态、最近诊断时间和进入诊断入口。
- 系统状态卡：Windows 版本、设备名、内存或系统盘概况。
- 空间维护卡：最近扫描时间、扫描结果和开始扫描入口。
- 应用状态：Toogl 版本、模块初始化错误或待处理恢复提示。

魔法工具卡可以使用更大的布局或更高的排序优先级，但所有已登记模块都必须可见并可进入。

### 3.3 数据规则

- 摘要卡由所属模块提供，复用模块 API、Store 和状态口径。
- 看板只负责布局、加载隔离、错误隔离和路由入口。
- 一个模块失败不能阻塞其他模块卡片。
- `未检查`、`未配置`、`检查中`、`不可用`、`失败`与`正常`必须区分展示。
- 看板进入时读取模块快照；不对所有模块做持续轮询。
- 卡片不能重新实现代理判断、网络判断、空间计算或系统信息读取。

## 4. 魔法工具

### 4.1 产品目标

完成以下最小闭环：

```text
启动 mihomo → 查看状态 → 选择节点 → 切换模式 → 开启系统代理 → 正常退出并恢复
```

魔法工具的页面结构：

```text
魔法工具
├─ 总览：内核、系统代理、模式、当前节点、错误与恢复
├─ 节点：代理组、节点选择、延迟和测速
└─ 节点来源：订阅链接、手动粘贴、更新状态
```

### 4.2 总览

展示：

- mihomo 运行状态、版本提示和启动失败原因；
- 系统代理开关及实际状态；
- 规则、全局、直连三个模式；
- 当前代理组和节点；
- 异常退出后的系统代理残留提示；
- 进入节点和节点来源页面的入口。

系统代理开启前必须保存 Windows 原状态；关闭或正常退出时必须恢复。异常退出后下次代理命令或状态查询应执行残留检查，并提供明确恢复入口。

第一阶段只做系统代理模式，不做 TUN、虚拟网卡、进程级代理或 PAC 管理。

### 4.3 节点

- 以 mihomo `/proxies` 为当前节点和代理组事实源。
- `selector` 组支持手动切换；`urltest`、`fallback`、`loadbalance`、`relay` 等组默认只读展示。
- 节点展示名称、协议类型、当前标记、测速状态和延迟。
- 页面可见时轮询代理状态，离开后停止；请求在途时跳过重复刷新。
- 节点切换失败必须回滚界面状态并展示可读错误。
- 测速为用户主动操作；单节点失败不拖垮其他节点；第一阶段不自动按最低延迟切换。

### 4.4 节点来源

订阅：

- 仅接受 HTTP/HTTPS URL。
- 支持含 `proxies` 的 Clash/mihomo YAML、Base64 分享链接列表和纯文本分享链接。
- 分享链接支持 `vless`、`ss`、`trojan`、`hysteria2`/`hy2`；暂不支持 `vmess`。
- 只提取节点，不用订阅内容覆盖本机整套规则、端口和其他配置。
- 支持保存链接、立即更新、后台 24 小时更新、最近成功时间、节点数量和最近错误。

手动导入：

- 支持多行文本或包含节点列表的文本。
- 逐条解析，坏行返回失败明细，其他有效节点继续导入。
- 同名手动节点覆盖旧手动节点；手动节点与订阅节点合并时手动优先。

统一更新链路：

```text
拉取/粘贴 → 解析 → 合并手动节点 → 托管文件原子写入 → mihomo 热重载 → 成功后保存元信息
```

热重载失败必须尽力原子回滚旧节点文件，并保留旧节点可用。用户手写的非 Toogl 模板配置不得静默改写；无法自动接线时返回明确的手工处理说明。

### 4.5 安全与生命周期

- mihomo controller 和代理入口默认只监听回环地址。
- controller 使用随机 secret 鉴权。
- 应用退出先恢复系统代理，再回收 mihomo 子进程。
- sidecar 启动失败只让魔法工具降级，不阻塞其他模块和看板。
- 不向前端开放任意配置键、任意命令或任意文件路径。

## 5. 网络诊断

### 5.1 目标

帮助用户判断固定测试目标的 DNS 和 TCP 可达性，辅助区分网络、代理和目标服务问题。不把局部测试结论表述为“整个网络正常”。

### 5.2 功能

- 执行固定目标的 DNS 查询，最多等待 5 秒。
- DNS 成功后执行固定目标的直连 TCP 检查，最多等待 3 秒。
- DNS 超时或失败时不继续 TCP 检查。
- 展示目标、步骤、结果、耗时和具体失败原因。
- 调用系统目录中的 `ipconfig.exe /flushdns` 刷新 DNS 客户端缓存。

不接受前端传入任意命令、参数、脚本或路径；不自动重置网卡、代理或网络配置；不自动提权。

## 6. 系统状态

只读展示：

- Windows 版本；
- 设备名；
- 处理器；
- 物理内存；
- 系统盘总空间、已用空间和可用空间。

使用 Windows 系统 API 获取事实，不把环境变量当作系统版本来源。不提供注册表优化、内存清理或静默系统修改。

## 7. 空间维护

第一阶段只扫描当前用户 `%LOCALAPPDATA%\\Temp`，不自动删除。

安全边界：

- 根目录为重解析点时拒绝扫描；
- 子项中的符号链接和其他重解析点跳过；
- 限制扫描数量、文件大小和执行时间；
- 不接受前端任意路径；
- 展示扫描时间、文件数量和估算空间；
- 扫描失败保留错误，不伪装为空目录。

未来若增加删除能力，必须逐项确认、显示副作用、隔离失败并提供可审计结果；不实现“一键深度清理”。

## 8. 软件设置

软件设置只管理 Toogl 自身偏好：

- 亮色主题；
- 暗色主题；
- 跟随系统主题；
- Toogl 版本和基本信息。

代理、订阅、扫描路径和网络诊断参数由所属模块管理。暂不显示没有真实实现的开机自启、窗口行为、置顶、TUN 等开关。

## 9. 配置与数据归属

| 数据 | 事实源或存储位置 |
| --- | --- |
| mihomo 存活、当前节点和代理组 | mihomo REST API |
| 规则模式 | mihomo REST API；本地记忆值只作降级展示 |
| 系统代理真实状态 | Windows 注册表 |
| 原系统代理备份 | `toogl.db` 的代理设置存储 |
| 订阅 URL、节点元信息、手动节点 | `toogl.db` |
| 托管节点 | mihomo 工作目录中的 `toogl-nodes.yaml` |
| 网络诊断结果 | 网络诊断模块状态；是否持久化按实际需求决定 |
| 系统信息 | Windows 只读 API，默认不持久化 |
| 空间扫描结果 | 空间维护模块状态，默认不持久化 |
| 主题 | `PreferenceStore` 的 app namespace，localStorage 仅作首屏缓存 |

Rust models 是跨语言契约唯一来源，TypeScript bindings 必须自动生成，禁止手改。

## 10. 非功能要求

- 安全：controller 默认只监听回环；不向前端开放任意命令和路径。
- 可靠：模块错误隔离；旧数据可读时后台刷新失败不得清空；订阅重载失败保留旧节点。
- 生命周期：页面轮询成对启动/停止；后台任务由 Rust 装配；退出清理系统代理和 sidecar。
- 性能：页面和较重资源按需加载；文件 IO 放后台；测速并发上限 16；避免重复初始化和过期响应覆盖。
- 类型：Rust 模型生成 TS bindings；IPC 命令与前端 `api.ts` 一一对应。
- 可维护：模块采用编译时登记；公共能力只有在存在多个真实调用方时才抽取。
- 测试：前端覆盖 Store、契约、轮询和错误回滚；Rust 覆盖解析、持久化、恢复、更新回滚和安全边界。

## 11. 产品验收清单

### 看板

- [ ] 首页默认进入看板。
- [ ] 魔法工具、网络诊断、系统状态、空间维护均有可见状态卡和入口。
- [ ] 魔法工具卡视觉优先但不隐藏其他卡片。
- [ ] 卡片数据与模块页面口径一致。
- [ ] 一个模块失败不影响其他卡片。
- [ ] 未检查、未配置、检查中、失败和正常状态区分明确。

### 魔法工具

- [ ] mihomo 可自动启动、可正常退出且无孤儿进程。
- [ ] 节点组和节点状态可读，selector 节点可切换。
- [ ] 规则、全局、直连可切换。
- [ ] 系统代理开启前备份，关闭和退出时恢复。
- [ ] 强制结束后下次启动可识别并恢复系统代理残留。
- [ ] 订阅更新成功后节点可用，失败时旧节点保留。
- [ ] 手动导入逐条容错，手动节点优先。
- [ ] 热重载失败后节点文件尽力回滚。
- [ ] 用户手写配置不会被静默覆盖。

### 其他模块

- [ ] 网络诊断只执行固定安全检查，DNS 失败不继续 TCP。
- [ ] DNS 刷新只调用固定系统命令，不接受任意参数。
- [ ] 系统状态只读展示。
- [ ] 空间维护限制 Temp 路径并跳过重解析点，不自动删除。
- [ ] 软件设置只显示已实现的应用偏好。

## 12. 明确不做

当前版本不做：

- TUN、虚拟网卡、进程代理、PAC；
- 自定义规则编辑器和完整 YAML 管理；
- 自动选最低延迟节点、自动故障切换策略 UI 和测速历史；
- 多订阅、云同步、远程 Hub、手机端、多用户；
- 游戏加速、流量统计、AI API 网关；
- 注册表清理、内存优化、一键网络重置；
- 未经用户确认的文件删除和系统修改。
