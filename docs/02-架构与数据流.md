# Toogl 架构与数据流

> 本文记录当前代码的架构事实与实现边界；产品能力范围见 [产品说明](01-产品说明.md)，进度与方向见 [开发状态与方向](03-开发状态与方向.md)。文档不得把未实现的规划写成已完成。

## 总体调用链

```text
Vue 页面 → 模块 Pinia Store / api.ts → Tauri invoke
  → apps/desktop/src-tauri/src/commands/ → crates/core
  → SQLite / Windows API / mihomo / 用户显式配置的外部 API
```

- commands 是薄壳：参数校验和状态装配在桌面端，业务在 `crates/core`。
- commands 统一返回 `Result<T, CommandError>`；前端用 `shared/errors.ts` 的 `toCommandError` 规整。

## 目录职责

| 目录 | 职责 |
| --- | --- |
| `apps/desktop/src/app/` | 模块登记（`modules.ts`）、路由（`router.ts`）、应用壳与导航 |
| `apps/desktop/src/modules/dashboard/` | 首页看板布局与卡片错误边界，不持有业务公式 |
| `apps/desktop/src/modules/proxy/` | 魔法工具：代理、节点、订阅和导入 |
| `apps/desktop/src/modules/settings/` | 主题偏好与版本信息 |
| `apps/desktop/src/shared/`、`components/ui/`、`lib/` | 通用错误、UI 与纯函数 |
| `apps/desktop/src-tauri/src/` | 桌面生命周期、commands、mihomo sidecar 管理 |
| `crates/core/src/` | mihomo、subscription、代理设置、系统代理、偏好和模型 |
| `crates/core/migrations/` | 只追加的 SQLite schema 迁移 |
| `packages/core-types/bindings/` | ts-rs 生成的跨语言类型，禁止手改 |

## 模块登记与路由

- `app/modules.ts` 是业务导航、业务路由与看板卡的唯一登记点，编译时静态声明 `id`、`title`、`icon`、`route` 和可选 `dashboard` 组件；规划中模块额外声明 `planned` 描述。
- 固定路由：`/dashboard`（看板）与 `/settings`（设置）在 `app/router.ts`；业务路由由 modules 展开注入。hash 路由。
- 看板按 `dashboardModules` 渲染卡片；单卡挂载失败由 `ModuleCardBoundary` 降级，不影响其他卡；`PlannedModulesCard` 由 `plannedModules` 生成规划中功能摘要。
- 规划中模块（信息订阅、AI 网关、系统优化、网络优化、开发环境）路由统一指向 `modules/planned/PlannedPlaceholder.vue` 占位页，侧栏"规划中"分组展示并带虚线徽标；占位页不发起任何业务 IPC。正式实现时替换 `route.component`、移除 `planned` 并补看板卡，步骤见 [模块开发指南](04-模块开发指南.md)。

## IPC 清单（当前）

| 命令 | 所属 | 说明 |
| --- | --- | --- |
| `app_preferences_get` / `app_preferences_set` | settings | 类型化主题偏好读写 |
| `proxy_status` / `select_proxy` / `test_delay` | proxy | 状态、节点切换、测速 |
| `set_system_proxy` / `switch_rule_mode` / `recover_system_proxy` | proxy | 系统代理与模式 |
| `subscription_status` / `subscription_set_url` / `subscription_update` / `import_share_text` | proxy | 订阅与手动导入 |

命令与前端 `api.ts` 一一对应；参数/返回类型来自 `@toogl/core-types`。

## 启动与退出

启动（`lib.rs`）：

1. 解析 `app_data_dir`，装配 `PreferenceState` 与代理状态。
2. 注册 commands；按需启动 mihomo sidecar（不阻塞页面）。
3. 前端首屏用 localStorage 主题缓存渲染，再以数据库偏好校准。

退出：

1. 先恢复系统代理（用 `proxy_setting` KV 中的备份值）。
2. 再回收 mihomo 子进程（`sidecar.rs`）。

顺序不可颠倒；sidecar 启动失败只让魔法工具降级，不阻塞其他模块。

## 魔法工具链

- `sidecar.rs`：端口探测、进程管理、`MIHOMO_EXPECTED_VERSION`（当前 v1.19.32）。
- `mihomo/client.rs`：REST API 调用；controller 只监听回环并保留 secret 鉴权。
- `sysproxy.rs`：Windows 系统代理读写；开启前备份注册表原值，关闭/退出时恢复。显式 trait 接缝 `RegistryIo` / `ProxyStateStore` 供测试注入内存实现。

## 订阅链路

```text
拉取/粘贴 → 解析 → 与手动节点合并（同名手动优先）→ 托管文件 toogl-nodes.yaml → mihomo 热重载
```

- 更新互斥：同一时间只允许一个更新流程。
- 热重载失败回滚节点文件，保持上一份可用节点。
- 24 小时后台更新由 Rust 侧 `tauri::async_runtime::spawn` 管理，不依赖页面打开。
- 解析覆盖 Clash/mihomo YAML、Base64 链接列表、纯文本分享链接（`vless`、`ss`、`trojan`、`hysteria2`/`hy2`）。

## 持久化

- `<app_data_dir>/toogl.db`：SQLite；`proxy_setting` KV 存代理数据、订阅元信息与手动节点；`preference` 表存普通偏好。
- `PreferenceStore` 使用类型化 namespace JSON；读取失败不当作首次使用写回默认值；旧值仅在迁移成功后删除。
- 迁移文件 `crates/core/migrations/NNNN_description.sql` 追加进 `db.rs::MIGRATIONS`，版本递增、语句幂等、同一事务登记。
- 主题 localStorage 仅作首屏缓存；诊断等会话内结果不持久化。

## 跨语言类型

- Rust `crates/core/src/models/` 是单一来源；`models/mod.rs` 的导出测试生成 `packages/core-types/bindings/`（含 `index.ts`）。
- 顶层 invoke 参数使用 camelCase；DTO 字段遵循生成类型的 serde 命名。
- 改 models 后运行 `cargo test -p toogl-core export_bindings` 更新 bindings；CI 用 `git diff --exit-code` 防漂移。

## 组件与封装

- `App.vue` 只装配布局；侧栏组件在 `app/components/`。
- 模块内组织：页面 + `api.ts` + 局部 `use*.ts` + 展示组件 + 可选 `components/OverviewCard.vue`；小工具不加空服务层。
- `components/ui/` 仅基础 UI（shadcn-vue），`shared/` 为跨模块交互，`lib/` 为纯函数。
- 异步约定：初始化请求复用、后台刷新保留可用缓存、旧响应不覆盖新状态、轮询成对启停且跳过隐藏窗口、乐观更新失败回滚。
