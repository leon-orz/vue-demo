### 1.2 数据流说明

| 数据流 | 路径 | 说明 |
|---|---|---|
| AI 用量统计 | 客户端本地读取 CLI 日志（kimi-code / MiMo / omp）+ 公网 HTTPS 直连各平台官方接口 | 只读聚合，不转发流量；Kimi 走 `/coding/v1/usages`，DeepSeek 走 `/user/balance`，MiMo 手录总额 + 本地日志推算 |
| 代理流量 | 客户端 mihomo sidecar → 境外 VPS mihomo 服务端 | api.openai.com / anthropic.com 等强制走稳定节点组 |
| 服务器控制 | 客户端 → Tailscale → 一体机 SSH / Docker API | 由中枢转发或客户端直连（取决于阶段） |
| 监控数据 | 一体机 Netdata（本机）/ 各设备 node_exporter | 浏览器走 Tailscale IP 访问 |
| 文件共享 | 客户端 → Tailscale → 一体机 Samba | 不暴露公网 |
| 远程开机 | 客户端/中枢 → 局域网广播 WoL 魔术包 → 一体机 | 要求同网段或有设备代发 |

**关键原则：一体机不开任何公网端口**，所有跨设备访问全部走 Tailscale。

## 2. 一体机初始化 **[待硬件到位]**

硬件参考配置（详见需求文档）：i5-13400/R5 7600、64GB DDR5、1TB NVMe 系统盘、机械盘按需、2.5G 网口。以下步骤假设系统盘为 NVMe，数据盘为后加的机械盘。

### 2.1 Debian 12 安装要点

1. 用官方 netinst 镜像制作 U 盘启动盘（Rufus / Ventoy 均可）。
2. 安装时：
   - 分区：NVMe 全盘自动分区即可（桌面工具箱场景不需要 LVM 精细划分）；**不要勾选桌面环境**，只勾 "SSH server" 和 "standard system utilities"。
   - 创建普通用户（示例用 `admin`，自行替换），设置强密码；root 密码留空则自动配置 sudo（推荐）。
3. BIOS/UEFI 设置：
   - 开启 **Wake-on-LAN**（网卡唤醒）和 **AC 掉电恢复自动开机**（Restore on AC Power Loss）。
   - 记录主板有线网卡 MAC 地址：`ip link show`，抄下来备用（WoL 需要）。

### 2.2 静态 IP

家用路由器上优先做 **DHCP 静态绑定**（按 MAC 固定分配，如 `192.168.1.10`），比在系统里写死更省心。若路由器不支持，编辑 `/etc/network/interfaces`：

```
auto enp1s0
iface enp1s0 inet static
    address 192.168.1.10/24
    gateway 192.168.1.1
    dns-nameservers 223.5.5.5 119.29.29.29
```

（网卡名用 `ip link` 实际看到的为准。）

### 2.3 SSH 加固

```bash
sudo apt update && sudo apt install -y openssh-server
```

在笔记本上生成密钥（若已有可复用）并推送公钥：

```powershell
# 笔记本 PowerShell
ssh-keygen -t ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh admin@192.168.1.10 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

一体机编辑 `/etc/ssh/sshd_config`：

```
PasswordAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
```

```bash
sudo systemctl restart ssh
# 先别关当前会话，新开一个终端验证密钥能登录后再退出
```

### 2.4 数据盘自动挂载 **[待硬件到位，按实际盘数重复]**

```bash
sudo mkfs.ext4 /dev/sdb            # 确认盘符！别格错系统盘
sudo mkdir -p /mnt/data1
sudo blkid /dev/sdb                # 抄下 UUID
```

`/etc/fstab` 追加一行（用 UUID，不用 /dev/sdb，防止盘序漂移）：

```
UUID=抄下来的uuid  /mnt/data1  ext4  defaults,noatime  0  2
```

```bash
sudo mount -a && df -h /mnt/data1  # 验证
```

> 多盘是否组 RAID/合并（mergerfs 等）：**待定**。NAS 形态未定死，初期建议单盘直挂 + 备份兜底（见第 6 章），后期按需演进。

### 2.5 Docker + Compose 安装

```bash
# 官方源安装（Debian 12）
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/debian/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/debian bookworm stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker admin      # 重新登录后免 sudo 用 docker
sudo systemctl enable --now docker # 开机自启
docker compose version             # 验证 compose 插件
```

本文档所有 compose 文件统一放在 `/opt/<服务名>/docker-compose.yml`，数据统一放 `/opt/<服务名>/data/`（或数据盘 `/mnt/data1/<服务名>/`），便于备份时一个目录一个目录地收。

### 2.6 Cockpit 网页管理面板（可选）

```bash
sudo apt install -y cockpit cockpit-storaged
# 默认监听 9090，浏览器访问 https://192.168.1.10:9090
```

> 端口提示：Cockpit 的 9090 在一体机上，mihomo sidecar 的 9090 在客户端本机，物理上不冲突；但如果你习惯端口一眼可辨，可在 `/etc/systemd/system/cockpit.socket.d/port.conf` 把 Cockpit 改成 9091。

### 3.1 中枢服务 hub（占位，随软件阶段二交付）

> **占位说明**：中枢服务是本项目另一编译产物（Rust，无界面），镜像/二进制与配置文件格式随《开发计划》阶段二交付，届时本节补齐。以下 compose 为**结构占位示例，不可直接运行**，端口与镜像名 **待定**。

`/opt/hub/docker-compose.yml`（占位）：

```yaml
services:
  hub:
    image: 待定            # 阶段二交付：自建镜像或二进制+systemd 二选一
    container_name: hub
    restart: always
    ports:
      - "待定:待定"        # 仅 Tailscale + 局域网可达
    environment:
      - TZ=Asia/Shanghai
    volumes:
      - ./data:/data       # 服务状态缓存 SQLite + 加密配置
```

部署前确认事项（阶段二验收清单）：

- [ ] 中枢可经 Tailscale 被客户端访问
- [ ] 中枢不可达时客户端自动降级为直连模式（功能验证，见 5.3）

### 3.2 Netdata 监控

`/opt/netdata/docker-compose.yml`：

```yaml
services:
  netdata:
    image: netdata/netdata:stable
    container_name: netdata
    hostname: toolbox-nas
    restart: always
    ports:
      - "19999:19999"
    cap_add:
      - SYS_PTRACE
      - SYS_ADMIN
    security_opt:
      - apparmor:unconfined
    environment:
      - TZ=Asia/Shanghai
    volumes:
      - ./data:/etc/netdata
      - /:/host/root:ro,rslave
      - /proc:/host/proc:ro
      - /sys:/host/sys:ro
      - /var/run/docker.sock:/host/var/run/docker.sock:ro
```

浏览器访问 `http://192.168.1.10:19999` 即可看到 CPU/内存/磁盘/网络/Docker 容器全量指标，开箱即用无需配置。

> 笔记本/台式机的监控（node_exporter 方案）属于阶段二软件联调内容，由软件侧展示，本文不展开；如需独立部署，在各设备跑一个 node_exporter 容器暴露 9100 端口即可。

### 3.3 Samba 文件共享

`/opt/samba/docker-compose.yml`（使用维护活跃的 dockurr/samba 镜像）：

```yaml
services:
  samba:
    image: dockurr/samba
    container_name: samba
    restart: always
    ports:
      - "445:445"
      - "139:139"
    environment:
      - NAME=Data
      - USER=smbuser
      - PASS=换成强密码
      - TZ=Asia/Shanghai
    volumes:
      - /mnt/data1:/storage
```

Windows 客户端访问：`\\192.168.1.10\Data` 或 `\\100.x.x.x\Data`（Tailscale IP），用户名 `smbuser`。

> 若以后要上完整的 NAS 系统（TrueNAS 等）或 NFS 共享：**待定**，按插件化设计，不影响软件层。

### 3.4 Tailscale（推荐宿主机直装）

Tailscale 建议**直接装在宿主机上**（而不是容器里），这样 Samba、SSH、Netdata 等所有服务天然可通过 Tailscale IP 访问，无需逐个配网络：

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
# 按提示用浏览器完成登录（Google/Microsoft/GitHub 账号均可）
tailscale ip -4        # 抄下 100.x.x.x，这就是一体机在私网里的固定地址
```

在 Tailscale 管理后台（Machines 页）建议：

- 对一体机关闭 Key Expiry（Disable key expiry），避免 180 天后掉线；
- 笔记本、台式机、VPS 全部加入同一账号/同一 tailnet。

若坚持容器化（不推荐，Samba 等服务要额外配网络）：

```yaml
services:
  tailscale:
    image: tailscale/tailscale:stable
    container_name: tailscale
    restart: always
    hostname: toolbox-nas
    environment:
      - TS_AUTHKEY=在管理后台生成的authkey   # 或首次 docker logs 看登录链接
      - TS_STATE_DIR=/var/lib/tailscale
    volumes:
      - ./state:/var/lib/tailscale
      - /dev/net/tun:/dev/net/tun
    cap_add:
      - NET_ADMIN
```

## 4. 境外 VPS 部署（阶段一即可做）

### 4.1 代理服务端安装要点

VPS 只跑一件事：代理服务端。mihomo 或 sing-box 二选一（**待定**，两者协议互通性有差异，按现有节点订阅格式决定；如果已有在用配置，直接沿用）：

- 安装：从各自 GitHub Releases 下载对应架构二进制，配 systemd 守护（或官方一键脚本，注意甄别来源）。
- 协议：用你当前自建节点已在用的协议（VLESS / Trojan / Hysteria2 等），不要为了本软件换协议。
- **管理端口安全（重要）**：
  - mihomo 的 `external-controller`（默认 9090）**只允许监听 127.0.0.1 或 Tailscale IP，绝不监听 0.0.0.0**；
  - 如开了 RESTful API，必须设 `secret`；
  - VPS 防火墙只放行：SSH（22，建议限源 IP 或仅 Tailscale）、代理协议端口（如 443）、Tailscale（41641/udp）。
- VPS 也装 Tailscale（同 3.4 命令），管理操作一律走 Tailscale IP。

### 4.2 节点管理思路

- VPS 是**自建稳定节点**，专供 Codex/Claude 等 AI 服务使用，IP 固定是核心资产。
- 客户端 mihomo sidecar 的配置里把该节点放进一个独立策略组（如 `AI-Stable`），规则把 `api.openai.com`、`anthropic.com` 等域名强制指向该组——具体规则文件随软件阶段一交付，本文只管服务端可用。
- 如果后续加了机场订阅作为备用节点：订阅链接写在客户端 sidecar 配置里，由软件负责更新，VPS 侧无改动。
- 定期检查 VPS 月流量套餐余量（自建节点流量超额直接被停机），可在软件增强阶段（阶段三）接流量图表。

## 5. 客户端部署

### 5.1 桌面软件安装

- 笔记本、台式机（Windows）安装 Toogl 客户端（Tauri 2 打包产物，安装包获取与签名方式 **待定**，随《开发计划》交付）。
- 首次启动后在设置页完成：
  1. **AI 用量统计**（阶段一）：填入 Kimi 开放平台的 API key（查余额用；key 存系统钥匙串，不落明文）；各 CLI 本地日志目录默认自动发现（kimi-code `~/.kimi-code`、MiMo `mimocode.db`、omp `~/.omp`），如有自定义路径（如 `KIMI_CODE_HOME`）则在设置里覆盖；MiMo 无公开余额接口，需在设置里手录套餐总额。
  2. **魔法工具**：确认内置 mihomo sidecar 已启动（见 5.2）。
  3. **中枢连接**（阶段二）：填一体机 Tailscale IP + 中枢端口，见 5.3。

### 5.2 mihomo sidecar 说明

- mihomo 由软件内置并托管启动，**不需要用户单独装 Clash**。
- 默认监听：代理端口 `127.0.0.1:7890`（mixed），RESTful API `127.0.0.1:9090`，仅本机可达。
- 软件一期功能：节点切换、系统代理开关、规则组切换（含 AI 域名强制走稳定节点组）。
- 配置文件由软件生成/更新，**不要手动改 sidecar 运行时配置**（会被覆盖）；要改就走软件界面或软件指定的配置目录。
- 排查入口：软件界面看 sidecar 状态；实在不行 `curl http://127.0.0.1:9090/proxies` 验证控制器活着。

### 5.3 连接中枢（阶段二）

1. 客户端装好 Tailscale 并登录同一 tailnet，确认能 `ping 100.x.x.x`（一体机）。
2. 软件设置 → 数据源：切换为"中枢模式"，填 `http://100.x.x.x:中枢端口`（端口待定，见 3.1）。
3. 验证降级：在一体机上 `docker stop hub`，客户端应自动提示并切回直连模式，余额刷新仍可用；`docker start hub` 后恢复中枢模式。

## 6. 备份策略 **[部分待硬件到位]**

总原则：**一体机一挂全挂，重要数据遵循 3-2-1**（3 份副本、2 种介质、1 份异地/离线）。以下备份脚本均为一行 cron 级别的简单方案，先跑起来再优化。

| 数据 | 位置 | 备份方式 | 频率 | 异地/离线副本 |
|---|---|---|---|---|
| 中枢数据与加密配置 | `/opt/hub/data/` | cron 每天打包到数据盘 | 每日 | 每周 rsync 到移动硬盘 **[待硬件到位]** |
| 客户端软件配置 | 各客户端本机（key 在系统钥匙串） | 阶段二后由中枢集中存/下发；阶段一自行导出备份 | 改动后 | 手动拷一份到 NAS |
| NAS 数据 | `/mnt/data1` | 增量 rsync 到移动硬盘 | 每周 | 移动硬盘即离线副本；特别重要的再传网盘冷备 |
| Tailscale/SSH 密钥 | 各设备 | 人工保管（密码管理器） | 变更时 | 密码管理器云同步 |

参考脚本（一体机 `/opt/scripts/backup.sh`，自行创建并 `chmod +x`）：

```bash
#!/bin/bash
set -e
DATE=$(date +%F)
DEST=/mnt/data1/backups/$DATE
mkdir -p "$DEST"
for svc in hub; do
  [ -d "/opt/$svc/data" ] && tar czf "$DEST/$svc-data.tar.gz" -C /opt/$svc data
done
# 移动硬盘挂载后手动或脚本追加：
# rsync -a --delete /mnt/data1/ /mnt/usb-hdd/nas-mirror/
```

cron（`crontab -e`）：`17 3 * * * /opt/scripts/backup.sh`（每天凌晨 3:17 执行）。

> 网盘冷备工具（rclone 等）与具体网盘选择：**待定**，需要时再补本节。

## 7. 日常运维与故障排查

### 7.1 服务自启与更新

- 所有 compose 服务均已 `restart: always`，Docker 本身 `systemctl enable docker`，重启机器后全自动拉起。
- 系统更新：`sudo apt update && sudo apt upgrade -y`，每月一次，内核更新后重启（先确认客户端没在跑长任务）。
- 镜像更新（以 Netdata 为例；hub 镜像构建流程待 3.1 节完善后同理）：

```bash
cd /opt/netdata && docker compose pull && docker compose up -d
```

- 是否引入 Watchtower 自动更新：**待定**。个人环境建议先手动更新、出问题可定位，稳定后再考虑自动化。

### 7.2 常见问题清单

| 症状 | 先查什么 | 常见原因与处理 |
|---|---|---|
| 客户端连不上一体机任何服务 | `ping 100.x.x.x` 通不通 | **先查 Tailscale**：两端是否都在线（`tailscale status`）、是否登录同一账号、key 是否过期被踢 |
| Tailscale 在线但服务不通 | 一体机上 `docker ps` | 容器挂了：`docker compose logs <服务>` 看日志，`docker compose up -d` 拉起 |
| 余额/用量不准或不刷新 | 软件内适配器状态 | 本地日志目录变动或权限问题：确认 CLI 日志路径可读；平台接口变了或 key 失效：按各平台官方接口手动 `curl` 验证（Kimi `/coding/v1/usages`、DeepSeek `/user/balance`）；中枢模式：`docker logs hub` |
| AI 网站走了错误节点 | 软件魔法工具页当前节点组 | 规则组被切走：切回 AI-Stable 组；VPS 节点失联：在 VPS 上 `systemctl status` 代理服务 |
| 系统代理没生效 | 软件内系统代理开关状态 | 被其他代理软件抢了设置：关掉冲突软件重开开关 |
| NAS 共享打不开 | `\\192.168.1.10\Data` 与 `\\100.x.x.x\Data` 都试 | 局域网通、Tailscale 不通→Tailscale 问题；都不通→一体机上 `docker logs samba` |
| 一体机没开机/唤不醒 | 路由器后台看设备是否在线 | WoL 需在 BIOS 开启且用对 MAC；局域网外唤醒需要网内有设备代发魔术包（中枢方案，阶段二） |
| 磁盘写满 | `df -h`、Netdata 磁盘页 | 多半是 Docker 日志：`docker system df` + `docker system prune` |

### 7.3 日志速查

```bash
docker compose logs -f --tail=200 <服务名>   # 在对应 /opt/<服务>/ 下执行
journalctl -u ssh -e                          # SSH 登录问题
tailscale status                              # 私网连通性
```
